# 10.08 — Apply to Debugging Task

A real model revises the executable workflow after observed failures. Its preflight and deduplication flags change host-side routing without changing the frozen evaluator. The lesson replays authentic attempts as a structural check, then inherits the descendant workflow in two fresh generations. All accepted and locally rejected proposals are recorded. A changed workflow is not itself evidence of better performance; no unsupported promotion is asserted.

Source: [pinned lesson](https://github.com/dlmastery/simple-coding-harness/blob/fabd4c79207df6a6a144c22fb1703fc074a048e7/10_research_studio/02_second_order_diagnostics/step_03_apply/README.md). This is an original QueryForge adaptation, not a reproduction of the source paper's benchmark results.

Prerequisites: complete M00–M03 and all preceding labs; `uv sync --locked`, authenticated Codex CLI, running Docker and checksum-verified TLC data. From the repository root:

```sh
uv run queryforge lab run 10.08
```

Input contracts are checked by the runnable lesson; failures stop execution rather than manufacture success. The output is [the actual JSON report](../../experiments/labs/10.08.json), which links the measurement or source evidence used. Read its interpretation together with the source-fidelity caveats. Missing source data, credentials or evidence is an error, not an offline simulation.
