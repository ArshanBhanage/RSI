# 10.14 — Simulate Self-HPO Alternation

The H-step changes the executable preflight harness with first-valid selection fixed. The P-step freezes that harness and uses a real model-selected discrete rule to select candidates from a larger generated pool. Actual SQL runs and both component versions are retained. This illustrates alternation over real data; the paper’s RL model-weight update is not implemented, and the report explicitly calls this a discrete-search pedagogical proxy.

Source: [pinned lesson](https://github.com/dlmastery/simple-coding-harness/blob/fabd4c79207df6a6a144c22fb1703fc074a048e7/10_research_studio/04_adaptive_workflows/step_03_selfhpo/README.md). This is an original QueryForge adaptation, not a reproduction of the source paper's benchmark results.
